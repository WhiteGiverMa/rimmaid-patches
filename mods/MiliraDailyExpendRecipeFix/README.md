# Milira Daily Expend：配方营养值修正

适用于 RimWorld 1.6 / 1.7 的纯 XML sidecar。依赖 Milira Daily Expend（工坊 `3604490167`），加载顺序在其之后。packageId：`whitegiver.miliradailyexpend.recipefix`。

## 问题

Milira Daily Expend 的 27 个配方全部继承原版 `CookMealBase`，但没有一个设置 `ingredientValueGetterClass`。原版 `CookMealBase` 本身也不设置它，而是每个烹饪配方单独写 `IngredientValueGetter_Nutrition`；默认值因此落到 `IngredientValueGetter_Volume`，`count` 被当作**物品个数**，小数向上取整。

结果：

- 账单显示 `2.5x 日光果实`，实际扣 3 个；`0.1x 日光大豆` 实际扣 1 个。
- 原料营养与产物营养完全不成比例：日光酱油一份 0.9 营养，却只花 1 米 + 1 豆（0.1 营养），比值 9 倍；可乐、果派、便当等又因为酱油/果酱营养值过高而倒挂。
- 「更多日光酱油」批量配方大米写成 60，单份 0.6 × 10 应为 6。

## 修改

1. **20 个纯食材配方**改用 `<ingredientValueGetterClass>IngredientValueGetter_Nutrition</ingredientValueGetterClass>`，`count` 全部改写为营养值。「要扣几个」换成「几个 × 单位营养」，所以绝大多数配方的实际扣料不变。
2. **日光酱油**营养值 0.9 → 0.1，**日光果酱**营养值 0.3 → 0.1。两者都是 `NeverForNutrition`，不影响进食，只作为配方原料计价；新值等于各自的原料成本。
3. **修三处失衡**（会改变实际扣料，属于有意重配）：
   - 卡利多八宝粥：植物生食 1 → 5 个（0.3 → 0.5，1.67 倍）
   - 土豆泥：土豆 1 + 牛奶 1 → 3 + 3（0.3 → 0.5，1.67 倍）
   - 更多土豆泥：土豆 5 + 牛奶 3 → 15 + 15（1.5 → 2.5，1.67 倍）
4. **更多日光果啤**果实 3 → 5，对齐单份比例。
5. **更多日光酱油**大米 60 → 10、大豆 1 → 10，对齐单份「1 米 + 1 豆」。
6. **含非营养原料的配方保持数量语义**：秘制酱汁烤鸡翅 ×2 用日光燃料、米跳墙用日光钢板。`IngredientValueGetter_Nutrition` 对无 `ingestible` 的物品返回 0，`ceil(count / 0)` 会溢出，因此不能切换；只把鸡翅的小数 0.2 改成整数 1。厨余垃圾与燃料配方本来就是数量语义，不动。
7. **Odyssey 配方用 `PatchOperationConditional` 守卫**：西天海鱼酱两条配方带 `MayRequire`，未装 Odyssey 时节点不存在；条件不命中就整段跳过，不产生 xpath 失配红字。

## 安装

把本目录的 `About/` 与 `Patches/` 复制为游戏 `Mods/MiliraDailyExpendRecipeFix/`，启用后重启游戏。必须排在 Milira Daily Expend 之后。

只改 Def，不改存档结构；停用后配方恢复上游原状。改动物品营养值不会影响已存在的物品堆，因为营养值来自 Def 而不是存档。

## 验证

```text
python Validation/validate.py
```

脚本读取本机工坊上游 XML，在内存里按 `Patches/Recipes.xml` 应用全部 61 个操作，然后核对：每个 xpath 恰好命中一次、20 个配方切到营养值、7 个配方保留数量语义、实际扣料个数、物品营养值与 20 条营养收支比值。不启动游戏，不写入上游目录。

游戏内最小验证：进入一局游戏，打开炉灶的账单，确认烹饪配方显示「x 营养值」而不是小数个数；做一份日光酱油，确认扣 1 米 + 1 大豆、产出 1 瓶。

## 维护与退役

上游更新后复核：

1. 27 个 RecipeDef 的 `defName` 与 `ingredients/li` 顺序保持不变；任一 xpath 失配会在日志里报 `PatchOperationReplace` 失败。
2. 上游若自行设置 `ingredientValueGetterClass`，先删除本补丁对应操作，避免重复添加。
3. 上游若调整日光酱油/果酱营养值或配方数量，重算本 README 的收支表。
4. 上游若新增含非营养原料的烹饪配方，不要套用营养值 getter。

本目录不包含上游 XML、贴图或 DLL，不自动上传创意工坊。
